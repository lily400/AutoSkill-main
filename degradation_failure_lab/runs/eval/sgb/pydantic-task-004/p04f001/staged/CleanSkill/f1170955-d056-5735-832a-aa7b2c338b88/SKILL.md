# Union 左到右短路匹配

按 Left to Right Mode 依次尝试联合成员：精确类型匹配立即返回，否则取最左的 strict 匹配，再退到最左的 lax 匹配；全部失败时返回所有错误。用于成员顺序具有优先级语义、希望精确匹配时快速短路的场景。

## Prompt

当联合成员顺序具有优先级语义、且希望在精确匹配时立即短路时使用本技能。执行时按声明顺序从左到右尝试每个成员：若某成员以精确类型匹配成功，立即返回该成员并停止评估后续成员；否则记录 strict 与 lax 匹配结果。全部评估后，若存在 strict 匹配则返回最左的 strict 匹配；否则若存在 lax 匹配则返回最左的 lax 匹配；若所有成员均失败，则返回全部错误。不要在此流程中引入基于有效字段数的评分选择（那属于 Smart Mode），也不要用于成员间存在明确判别字段的场景。

## Objective

按成员顺序与匹配严格度短路返回首个可接受结果
## Applicable Signals

- 联合成员顺序具有优先级语义
- 希望精确匹配时立即返回而不评估后续成员

## Contraindications

- 需要基于有效字段数评分选择（应使用 Smart Mode）
- 成员间存在明确判别字段（应使用判别联合）

## Intervention Moves

- 按声明顺序从左到右尝试每个联合成员
- 精确类型匹配成功时立即返回该成员并停止评估
- 记录 strict 与 lax 匹配结果用于回退
- 全部评估后优先返回最左的 strict 匹配，其次返回最左的 lax 匹配
- 全部成员失败时返回所有错误

## Workflow Steps

- 按声明顺序从左到右尝试每个联合成员
- 若某成员以精确类型匹配成功，立即返回该成员并停止评估后续成员
- 否则记录 strict 与 lax 匹配结果
- 全部评估后，若存在 strict 匹配则返回最左的 strict 匹配
- 否则若存在 lax 匹配则返回最左的 lax 匹配
- 若所有成员均失败，返回全部错误

## Constraints

- 严格遵循成员声明顺序
- 精确匹配必须立即短路，不评估后续成员
- 回退顺序固定为 strict 优先于 lax，且均取最左匹配

## Cautions

- 成员顺序会直接影响结果，调整顺序可能改变返回的成员
- 若需要基于有效字段数评分选择，应改用 Smart Mode

## Output Contract

- 返回首个精确/strict/lax 匹配成员，或全部失败时返回所有错误

## Triggers

- 联合成员顺序具有优先级语义
- 希望精确匹配时立即返回而不评估后续成员
- 需要按 strict/lax 严格度回退选择联合成员
