# 无效或不完整输入处理

在批处理前对结构化输入（如 JSON 产品目录）执行有效性校验，识别缺失字段、格式异常或目录无效的情况，并给出可追溯的降级处理动作，避免产出错误的结构化结果。

## Prompt

在开始批处理或结构化产出前，先校验输入是否为有效 JSON 且结构完整。检查必需字段是否存在、字段类型是否符合要求、标识是否与目录一致。若输入缺失、格式错误或目录无效，判定为无效输入并记录处理动作（如拒绝处理、请求补充或降级），不要继续产出结构化结果。

## Objective

识别并处理无效或不完整输入
## Applicable Signals

- 输入为 JSON 目录或结构化数据
- 存在缺失字段或格式异常风险
- 批处理即将开始
- 输入缺失
- 输入格式不符合预期
- 产品目录JSON校验失败

## Contraindications

- 输入已确认完整且格式合规
- 输入完整且通过校验时无需触发本规则

## Intervention Moves

- 校验输入是否为有效 JSON
- 检查必需字段是否齐全
- 检查字段类型与取值是否合规
- 判定输入有效性并记录处理动作
- 校验输入完整性与格式
- 校验产品目录JSON
- 对无效输入按规则给出明确处理结果或错误提示

## Workflow Steps

- 确认输入为 JSON 目录或结构化数据
- 校验 JSON 可解析且结构完整
- 检查必需字段是否存在、类型是否合规
- 判定输入有效性
- 对无效或不完整输入执行降级处理并记录动作
- 检查输入是否存在且格式符合预期
- 校验产品目录JSON是否有效
- 若发现无效或不完整输入，停止后续分析并按既定规则输出明确的处理结果或错误提示

## Constraints

- 仅在批处理前的输入把关阶段使用
- 输入已确认完整且格式合规时不再执行
- 无效输入不得继续进入结构化产出
- 不得静默失败
- 不得在输入无效时继续执行后续分析步骤

## Cautions

- 避免在输入未校验时直接产出结构化结果
- 降级处理动作需可追溯
- 错误提示需明确指向无效或不完整的输入部分

## Output Contract

- 输入有效性判定及处理动作记录
- 明确的无效输入处理结果或错误提示

## Triggers

- 输入为 JSON 目录或结构化数据
- 存在缺失字段或格式异常风险
- 批处理开始前的输入把关
- 输入缺失或格式不符合预期
- 产品目录JSON校验失败
