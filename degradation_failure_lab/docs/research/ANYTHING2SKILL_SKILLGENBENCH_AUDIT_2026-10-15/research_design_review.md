# 双路径退化研究：独立设计审稿备忘录

日期：2026-10-15。性质：研究设计裁决，不实施实验。依据：用户完整原始要求、本轮 `sgb_runtime_audit.md`、`anything_audit.md`、来源清单与离线 Oracle 反例；另核对 [Skill-α 最新 v3，2026-10-10](https://arxiv.org/html/2608.01678v3) 和 [Ctx2Skill v1](https://arxiv.org/html/2604.27660v1)。下面的“应当”“可以”均为未来协议，不是已完成结果。

## 一、先界定能估计什么

设独立来源组为 s，预先固定来源内任务集 T_s，路径 p∈{S=冻结 Skill，D=DirectDoc}，文档条件 c∈{0=Clean，R=相关退化，U=无关退化}。Y 是经验证 Oracle 的逐次成功指示，不能使用当前程序 any-success 命名的 pass_rate。对生成随机性和执行随机性求平均，再在每个来源内部按预注册任务权重平均，得 μ_s,p,c。

最小主要估计量：

```text
L_p(c) = mean_s[ μ_s,p,0 - μ_s,p,c ]
Δ(c)   = L_S(c) - L_D(c)
Θ      = Δ(R) - Δ(U)
```

Δ(R)>0 表示在明确预算和资料权限下，Skill 工作流的退化损失比 DirectDoc 大；Θ 进一步扣除所定义无关扰动造成的损失。该六格是配对干预实验，不需要假借时间序列“平行趋势”；但 Θ 的“相关性特异效应”解释要求 R/U 的修改类型、幅度、位置/长度代价尽量匹配。仅把一边删规则、一边加无关句子不能达到这一点。

必须同时给六格原始成功率、Clean 水平、源级差值、生成/加载/环境失败率。Clean Skill 接近零时损失也接近零，不能因此称鲁棒；相对下降率在低基线时也不稳定。分别报告规则保留、规则语义正确、关键动作和任务结果，避免仅成功率。

**这个估计量是“预计算并冻结技能”与“任务时读文档”两种工作流的总效果。** 两者的处理时机、压缩、额外生成计算本来就是处理的一部分。固定 executor 并不能把它变成纯粹 SKILL.md 表示格式的因果效果。如果要拆分表示形式，需另加时间/总计算受控的对照，不能用六格自行推断。

任务无关主线必须每来源×条件先生成一次完整 bundle，冻结后再暴露任务；不能逐任务重新提取。生成随机性需独立重复 bundle，执行重复嵌套在同一个 bundle 下；增加 Agent seeds 不会增加独立文档/独立生成样本。每条件各用空 SkillBank，不能让 Clean 产物泄漏到 Degraded 注册检索。

统计单位优先为来源家族（原文、库生态/版本、同文变体均同组），不是任务、Skill 或测试 case。主分析来源等权，任务加权结果作次要视角；按来源整组 bootstrap 或分层模型，重采样保留六条件、bundle和任务的依赖关系。少量来源时区间极不稳定，应给逐来源效应并限制为案例性结论；1–3任务只验证识别链路，不估总体效应。最终样本数应由预期效应与源间方差的事前功效/精度目标决定，不能指定任意“≥N就足够”。

## 二、最低公平信息边界

| 环节 | Skill 主线 | DirectDoc 主线 | 必须共同锁定 |
|---|---|---|---|
| 生成时 | 只看同条件 source corpus，任务隐藏，冻结完整 bundle | 无预生成 Skill | 文档快照、退化操作、独立空状态；禁止答案/verifier/gold/任务定向人工筛选 |
| 任务时 | instruction+input+冻结技能；无 source corpus | 相同 instruction+input+同条件 corpus；无预生成技能 | executor实际模型、工具、运行库、网络、环境起始状态、时限/调用/输出预算 |
| 检索读取 | 以任务检索冻结库，策略预注册 | 以任务读取/检索对应文档，策略预注册 | 同类文件读取/检索工具；记录实际读取内容和token；不得给Skill免费oracle选择 |
| 评价时 | agent结束后独立 verifier | 相同 verifier | tests/groundtruth不给agent；标准正反例验收；逐trial分母固定 |

不能要求两路径“看到完全相同文本”，那会消除研究干预；要求的是同源语义信息可获得性、共同 runtime 约束和透明的计算账本。主估计可以固定在线预算，并单列生成成本、按使用任务数摊销；若宣称总成本优势，再做总预算匹配，不能既给Skill额外生成预算又称完全等算力。不要简单截断 DirectDoc 到技能长度，人为删除可用证据来实现“公平”。长文若需要检索，检索规则对全部条件固定并计费；另做匹配相关证据的诊断对照，不能静默变主线。

Agent 自行在工作区写摘要是一般推理行为；若禁止持久化跨任务笔记，则两路径同样清空跨任务状态。任务间唯一允许复用的对象为指定冻结技能或固定文档，避免学习顺序混杂。执行顺序随机交错，代理/模型更新窗口一致。

本轮代码已证明默认挂载清洁 docs、tests、groundtruth，必须隔离；否则 Skill 条件实际是 Skill+Doc，不回答用户的双路径问题。对 Code Repo 任务，参考仓库往往同时是执行依赖和知识来源，若不能分离，不能纳入 skill-only 主分析；可单列 repository-access stratum。

## 三、11种失败的可观测判定树

先查协议/Oracle/环境，再讨论生成；采用“首个可定位失效环节+并存标签”，不能把最先发现的问题宣称唯一因果原因。

```text
权限、任务信息与预算相等？ --否--> [11]协议不等，终止方法比较
        ↓是
Oracle正反例有效且环境跑通？ --否--> [10]评价器 / [9]环境，终止能力归因
        ↓是
源文存在足够可恢复证据？ --否--> [1]输入不足，进入缺知识诊断而非鲁棒性主集
        ↓是
正确目标规则存在于冻结原始产物？ --缺失--> [2]提取/编译遗漏
        ↓存在但错---------------------------> [3]语义错误
        ↓存在且正确
规则/技能与任务依赖相匹配？ --否--> [4]目标不匹配
        ↓是
需要的包/规则经adapter完整交付？ --否--> [5]转换/多技能覆盖
        ↓是
预期skill实际成功加载？ --否--> [6]发现/加载
        ↓是
规则要求的关键动作发生？ --否--> [7]决策/遵循，或[8]执行能力不足（需正控制区分）
        ↓是
动作执行及最终状态正确？ --否--> [9]工具环境或[8]能力；回查[10]oracle
        ↓是
任务通过；仍不等于所有技能内容正确
```

| 编号与失败 | 必须记录的观察量 | 最小排查/结论边界 |
|---|---|---|
| 1 文档不足 | 原子规则的来源段、必要前提、退化后残存证据、人工可恢复性 | 独立标注者只看退化资料能否还原目标命题；全删唯一知识列不可恢复。DirectDoc失败不能单独证明资料不足。 |
| 2 未提取 | source→实际window payload→draft→spec→canonical各层规则覆盖 | 源有、window无是前端暴露失败；window有、输出无再定位extract/compile/register，不混称LLM理解差。 |
| 3 规则语义错误 | 条件/量词/否定/例外/动作/边界真值表，证据蕴含标注 | 盲审原子命题；局部修复仅作诊断；不能用LLM自报confidence当正确。 |
| 4 目标不匹配 | 预先定义rule-task依赖矩阵、任务路由结果 | 库名相同不构成依赖；正确技能被错误任务调用是匹配错误。 |
| 5 多Skill只送一份/转换 | canonical/导出/安装完整文件hash与规则清单，引用存在 | 原始产物有但投影缺，归adapter；选择/拼接必须是独立因素。 |
| 6 未发现/未加载 | 预期包名和hash、Skill tool use与成功result配对、实际返回内容 | 当前trigger布尔不够；安装成功≠加载成功；错误tool result不算加载。 |
| 7 加载未遵循 | 可观察命令/API参数/中间文件/最终状态与规则要求一致率 | 依据外显动作而非编造隐藏思维；随机配对repair/damage能增强归因，但需排除路由变化。 |
| 8 Agent能力不足 | GoldSkill/显式正确动作计划条件、确定性动作重放 | 确定性正确动作可执行但多次Gold仍失败，支持执行器瓶颈；一次Gold失败非定论，Gold本身也须验证。 |
| 9 环境/依赖 | image digest、工具版本、退出码、日志、正确提交物同环境执行 | 不计生成语义错；原样保留失败并单列infra率。需预注册最大重试。 |
| 10 Oracle/任务定义 | 正提交应通过、最小语义错应失败、边界输入、契约一致性 | 当前scikitimage硬编码通过及domain NaN自比失败已是反例；未修的oracle不可支撑方法排名。新oracle另版本。 |
| 11 条件信息不等 | 全部prompt/source/skill manifests、任务可见时间、工具可达路径、预算 | task-conditioned A2S单独命名；hidden tests、公平预算任一泄漏均阻断生成能力因果结论。 |

全条件失败：优先否定测量链已建立的假设；只有 Oracle 和确定性动作正控制先通过，才进一步讨论Agent或文档。NoSkill成功、OriginalSkill失败：仅是负迁移候选；需重复配对，确认同环境/预算，排除加载挤占token、错误路由，局部修复/破坏选择性改变同一关键动作才支持特定错误规则引发负迁移。

这些诊断对照可以超出2×3主设计，但不得混成更多“方法结果”。Generation/adapter/load失败的任务在预注册全流程效果分母中保留；语义分析另报告可审计子集及分母变化，不能按试验成功率事后删例。

## 四、repair / damage / sham 的可识别范围与防泄漏

在事前锁定目标规则r及依赖任务集合 T+、非依赖集合 T−后，用相同原始skill产生：Original、Repair（纠正该错误）、Sham（编辑等量相近位置而语义不变）。Damage从已确认正确的Clean skill出发反向改坏同一规则；另设对应Clean-sham。不要假装所有自然错误都能找到对称反向操作。

最小局部选择性指标：

```text
RepairSelectivity = mean_T+[Y(Repair)-Y(Sham)] - mean_T−[Y(Repair)-Y(Sham)]
DamageSelectivity = mean_T+[Y(CleanSham)-Y(Damage)] - mean_T−[Y(CleanSham)-Y(Damage)]
```

同时报告相对Original差和关键动作正确率。非依赖任务“未显著变化”不等于稳定；须事前设实质等价容忍区间，并以区间是否落入范围判断。1个控制任务能提供个案对照，不能证明一般选择性。

防泄漏最低规则：

1. 规则标注/修复者只看源文与目标原子命题，不看held-out答案、测试输出、失败trace或test实现；若根据开发trace发现错误，随后测试用未见任务/合法变体。Gold另存，仅给正控制执行器，绝不回流生成器或共享SkillBank。
2. 修改只恢复源文已支持的一般条件/例外/动作，不添加具体任务输入、预期数字、文件终态、隐藏test分支或task ID。一个通用patch原样用于所有依赖任务与控制任务，不能逐题手调。
3. 冻结包名、frontmatter描述、目录、顺序、文件数、路由、loader和prompt。除目标最小文本区间外字节保持不变；记录diff和hash。名字变化导致检索变好不叫规则语义修复。
4. Sham匹配编辑位置和近似长度/句法改动，保留目标语义；不能在sham里额外暗示正确答案。不要为了精确token等长引入有新含义的padding。独立复核目标规则确已改变、其它规则未变。
5. 规则在多个章节/技能中重复时，必须事前决定“编辑一个位置”还是“改动全部同一规则实例”。前者测局部文本干预且可能留冲突；后者测bundle级规则干预并完整列diff。两者均不可声称天然单规则无副作用。
6. 干预臂标签不出现在Agent可见路径或内容；执行顺序随机，fresh workspace，重复而不择优；编辑方案在held-out运行前锁定。

**局部编辑实验识别的是artifact级受控干预效果，不自动识别“文档退化经该规则造成结果”的自然中介效应。** 后者还需退化确实导致规则改变、其它语义/检索路径不被编辑影响、规则改变对应关键动作改变等额外证据；多条中介相互影响时不能声称“解释了全部退化损失”。人工repair使用清洁证据只给诊断上界，不能当作不访问清洁源的改进算法成绩。

共享传播至少要一个冻结bundle、2个真正依赖同一规则的任务和1个非依赖任务。多次运行同一个任务不是多任务；对同题新建输入变体可增加规则检验，但独立样本仍是原题/来源家族，标为扩展集。现有36个domain来源各1任务，Code Doc四个≥3任务的库仅提供计数上候选，尚不证明规则三联组存在。

## 五、创新性：当前应降低而非提高承诺

Ctx2Skill已从复杂context通过自博弈发现/更新/选择规则技能，其公式(2)执行时仍输入原context C和技能S；因此它是近邻，但原版不等于skill-only对照，改成skill-only须披露。[官方方法§3.2–3.3](https://arxiv.org/html/2604.27660v1#S3.SS2)

Skill-α v3已把技能构造分解为局部编辑，并以同一anchored query上原/编辑技能的rollback比较训练；还研究证据重排/粒度，并含AutoSkill4Doc与Ctx2Skill比较。不能把“局部修复前后比较”或“从文档生成skill”当新意。[官方§4.2、§5.4、附录B.2](https://arxiv.org/html/2608.01678v3#S4.SS2)

可能独立但尚未证明的贡献是：**可恢复的结构/证据可访问性退化，是否使预编译技能产生比任务时读文档更持久、相关的规则误编译风险；此风险能否由预注册的原子规则干预在多个真依赖任务上选择性改变。** 这比泛化的技能编辑/RL问题更窄，仍需数据三联组、可信Oracle和多来源重复。不应把近邻未专门写“degradation”当作 novelty 已通过；还需系统近邻检索和实证差异。

若最终只有clean/degraded表、若干成功率和事后挑的修复例，研究价值裁决应为FAIL/NO-GO；若能形成跨来源可证伪机制规律但暂没有新算法，可定位严谨诊断研究，而不能称已提出高质量生成算法。

## 六、必须NO-GO的结论和唯一首要验证

当前 **NO-GO 于正式付费大规模实验、直接报官方成绩、共享规则因果结论、宣称论文创新已成立**。只允许在用户另行授权后继续确定性接线/测量链验证。以下任一项发生则相应主张停止：

- 未修Oracle正反例/JSON/TOML/技能路径，即比较Anything2Skill生成质量；默认清洁docs旁路仍存在，即比较skill-only与DirectDoc。
- Clean目标证据在输入窗口已缺失，或Clean规则已错误，却把新退化差值解释为从正确规则到错误规则的生成链；该例应保留Clean失败诊断，不是偷删。
- 必要唯一证据被完全移除，却称为可恢复退化；任务条件可见性不等，却称生成方法公平比较。
- 没有已证实的2依赖+1控制三联组，却声称共享传播；只重采样同源任务却给来源泛化置信区间。
- repair改变路由/多个独立规则，或sham产生同样改进且机制不明，却声称特定规则中介成立。
- Gold、DirectDoc、Original、Repair均失败且正确动作链未通过；无论失败多少次，都不能判Anything2Skill独有生成能力不足。

**首先验证的唯一关键假设：对一条来源充分支持的目标规则，固定接口和环境下存在一对只在该规则后果上不同的正确/错误提交或动作，Oracle能稳定接受前者、拒绝后者。** 先用确定性动作/提交物验证，完全不需要调用模型。它若不成立，所有后续成功率、repair与damage均无解释基础；它若成立，也只放行下一道“实际成功加载与执行”门，不等于整体GO。
