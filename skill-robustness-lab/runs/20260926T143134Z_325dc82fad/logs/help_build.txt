Read documents, extract support-backed skill drafts, compile canonical skills, and register versions.

options:
  -h, --help            show this help message and exit
  --file FILE           Single file or directory containing offline documents.
  --title TITLE         Optional document title override for inline input.
  --domain DOMAIN       Optional domain hint, e.g. psychology or chemistry.
  --domain-type DOMAIN_TYPE
                        Selected taxonomy domain type. This is user-provided
                        configuration rather than model output.
  --skill-taxonomy SKILL_TAXONOMY
                        Optional custom skill taxonomy YAML path. Built-ins:
                        chemistry, default, psychology.
  --source-type SOURCE_TYPE
                        Generic source type label stored with imported
                        documents.
  --extract-strategy {recommended,strict,chunk}
                        Window planning strategy used during ingest.
                        `recommended` currently resolves to strict windows.
  --registry-root REGISTRY_ROOT
                        Override the document registry root. Default:
                        <store>/.runtime/document_registry.
  --store-path STORE_PATH
                        AutoSkill4Doc store path. Default:
                        <repo_root>/SkillBank/DocSkill.
  --hint HINT           Optional extraction hint stored in metadata.
  --family-name FAMILY_NAME
                        Optional visible family name used for the exported
                        parent/child skill tree, e.g. 认知行为疗法.
  --profile-id PROFILE_ID
                        Optional profile id recorded into visible skill tags
                        and manifests. If omitted, one is derived from
                        taxonomy + family_name.
  --taxonomy-axis TAXONOMY_AXIS
                        Optional family axis label recorded into visible skill
                        tags and manifests. If omitted, the selected taxonomy
                        may provide a default.
  --continue-on-error   Continue processing remaining documents after one
                        document fails. This is the default.
  --fail-fast           Stop immediately on the first document error.
  --dry-run             Run without persisting registry or store changes where
                        applicable.
  --json                Emit machine-readable JSON output.
  --quiet               Suppress stage logs and only print final output.
  --max-documents MAX_DOCUMENTS
                        Limit how many files are read when --file points to a
                        directory. 0 means no limit.
  --llm-provider LLM_PROVIDER
                        LLM provider id used by AutoSkill4Doc. Defaults to
                        auto-detection from environment.
  --llm-model LLM_MODEL
                        LLM model id.
  --llm-base-url LLM_BASE_URL
                        Optional LLM base URL.
  --embeddings-provider EMBEDDINGS_PROVIDER
                        Embeddings provider id.
  --embeddings-model EMBEDDINGS_MODEL
                        Embeddings model id.
  --embeddings-base-url EMBEDDINGS_BASE_URL
                        Optional embeddings base URL.
  --embeddings-dims EMBEDDINGS_DIMS
                        Embedding dimensions for hashing/mock providers.
  --maintenance-strategy {heuristic,llm}
                        Store maintenance strategy.
  --max-section-chars MAX_SECTION_CHARS
                        If one detected section is longer than this many
                        characters, pre-split it before final extraction
                        windows are built.
  --section-outline-mode {llm,rule,auto,off}
                        How to determine section/subsection hierarchy. `llm`
                        is the default and runs one outline LLM pass per
                        document over rule-recalled heading candidates; `rule`
                        disables the LLM pass. `auto/off` are compatibility
                        aliases.
  --max-chars-per-chunk MAX_CHARS_PER_CHUNK, --max-chars-per-window MAX_CHARS_PER_CHUNK
                        Maximum characters per extraction window/unit. Short
                        sections stay whole; long sections fall back to
                        smaller windows.
  --overlap-chars OVERLAP_CHARS, --window-overlap-chars OVERLAP_CHARS
                        Overlap used when a long section/window must be split
                        into fallback units.
  --max-candidates-per-unit MAX_CANDIDATES_PER_UNIT, --max-candidates-per-window MAX_CANDIDATES_PER_UNIT
                        Maximum planned skills expanded for each extraction
                        window/unit.
  --max-units-per-document MAX_UNITS_PER_DOCUMENT, --max-windows-per-document MAX_UNITS_PER_DOCUMENT
                        Limit how many extraction windows/units are sent to
                        the model per document. 0 means no limit.
  --extract-workers EXTRACT_WORKERS
                        Document-level extraction workers. Each worker
                        processes one document at a time; windows inside one
                        document remain sequential.
  --extract-retries EXTRACT_RETRIES
                        Retries for transient extraction failures such as rate
                        limits, overload, or temporary network errors.
  --extract-retry-backoff-s EXTRACT_RETRY_BACKOFF_S
                        Base backoff seconds for extract retries; exponential
                        backoff is applied per retry.
  --llm-rate-limit-requests LLM_RATE_LIMIT_REQUESTS
                        Maximum LLM requests allowed within one rolling rate-
                        limit window. 0 disables proactive throttling.
  --llm-rate-limit-window-s LLM_RATE_LIMIT_WINDOW_S
                        Rolling window size in seconds used together with
                        --llm-rate-limit-requests.
  --retrieval-score-threshold RETRIEVAL_SCORE_THRESHOLD
                        Minimum retrieval score required before similar-skill
                        or parent hits are kept for downstream versioning
                        decisions.
  --target-state {candidate,draft,evaluating,active,watchlist,deprecated,retired}
                        Lifecycle state to assign to newly registered skills.
