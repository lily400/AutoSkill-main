# 统一数据规范 v4

本规范在第一阶段报告完成后制定。支撑的目标是可审计的配对生成和下游执行评测；schema通过只代表数据结构满足协议，不代表语义或任务正确。当前数据只迁移case001，不创建第二案例、退化或模型结果。

## 1 身份 版本 和状态

所有JSON使用UTF-8、schema_version="4.0"。ID为非空ASCII字母数字、连字符、下划线、点；不得含路径分隔符。文件路径为相对工程根的POSIX路径，拒绝绝对路径、`..`、反斜线、符号链接越界。ID与路径均区分大小写；Windows下额外拒绝大小写重复路径。SHA256为64位小写十六进制，版本改变必须创建新版本对象。

| 标识 | 唯一职责 | 不应混用 |
|---|---|---|
| case_id | 一个源规格/测试集合版本的实验案例，如case001-v2 | case_key只是本地目录名；旧case001-dev-v1保留在迁移备份，不复用其冻结身份 |
| source_id + source_version | 一个有边界的来源流程与该流程的材料版本 | 不是每个退化一个新source；同源改写随原来源分组 |
| family_id | 研究上的同源/模板/近重复分组，决定split和bootstrap cluster | official.family_name及官方taxonomy family_id不用于研究划分 |
| variant_id | source某版本的一份固定文档条件 | 不包含生成repeat；同一变体可多次生成 |
| task_id | 一份固定执行输入和判题目标 | 不是案例或生成run |
| run_id | 一个方法×变体×生成重复的一次尝试 | preflight独立编号；重试新run并保留attempt关系，不能覆盖失败 |
| execution_id | 一次技能/参考实现/无技能对某task的执行尝试 | 生成run可以关联多个execution；judge独立引用execution |

**[已有证据支持]** 旧case.task.family_name是传入官方CLI的标签；旧contract与fixtures都是设计期标准。**[当前代码未实现]** 大多数研究ID和独立执行实体。以下为第三阶段实现目标。

状态不互相替代：`draft`尚未冻结；`pending`某项审查待进行；`not_run`尚未尝试；`running`已启动；`completed`过程完成；`failed`有错误证据；`blocked`前置条件不满足；`not_applicable`该方法不使用。`null`只表示没有值，必须与status/reason一起出现。判题`passed`只用于真实执行后符合版本化标准。生成的结构通过另记`structural_pass`。

## 2 文件与权限边界

目标布局（尖括号为未来实体，不创建虚假JSON实例）：

```text
skill-robustness-lab/
  README.md
  configs/
    environment.json                    # 用户指定Python、官方只读目录、密钥文件路径
    methods/{chunk,strict}.json         # 官方原生生成参数
  catalog/
    cases.json                         # 注册真实case manifest路径
    families.json                      # 研究family对象列表
    split.json                         # 全体source/family分组分配和开发用途
    freeze.json                        # 固定标准与文档的完整封存清单
  cases/case001/
    case.json
    source.json                        # 来源流程元数据
    clean/source.md                    # 保留原始开发文档字节
    variants/clean.json
    variants/<variant_id>.json
    degradation/<degradation_id>.json
    degradation/files/<variant_id>.md
    degradation/generators/<version>.py
  standards/case001/
    contract.json                      # 规则原文；没有verdict/执行分数
    fixtures.json                      # 11项原有开发输入/答案，迁移对照兼容文件
    tasks/<task_id>.json                # 每个输入的身份、用途和规格引用
    judge.json                         # 判题实现/版本/覆盖限制
    reference/                         # 若有人工参考IR/技能，隐藏于执行器
  scripts/
    schema_defs.py                     # 类型及JSON Schema导出
    data_contracts.py                  # schema子集校验、关联、划分、封存
    validate_data.py                    # 无网络验证与冻结入口
    run_case.py, run_one.py             # 生成入口和隔离运行
    official_entry.py, trace_http.py    # 不改官方文件的调用与裁剪观测
    evidence.py, audit_run.py           # 原证据收集与完整性核查
    compare_runs.py                     # 同方法clean/degraded配对，无伪造分数
    reference_csv.py, judge_csv.py      # case001开发参考实现和确定性检查
    execution_tools.py                 # reference离线验收/执行状态接口
  schemas/<object>.schema.json          # 每类对象的机器可读字段/枚举
  tests/test_*.py                       # 隔离临时数据负测试，不是研究案例
  runs/<run_id>/
    run.json, status.json, checksums.json
    input/source.md                    # 本条件输入，退化运行不能附clean副本
    config/                            # 方法/来源ID/代码/环境/指纹/官方源码快照
    trace/                             # 实际模型调用与裁剪记录
    logs/
    official/                          # 完整官方原生产物，不转换为IR
    tmp/
  executions/<execution_id>/
    execution.json, checksums.json
    workspace/                         # task输入、技能包、授权工具和实际输出
    evidence/                          # 进程日志、返回码、输入前后哈希
  judgments/<judgment_id>/
    judgment.json, checksums.json       # 引用execution，依据和检查项
  semantic_reviews/<review_id>.json     # 独立人工语义判断，未来新增
  comparisons/<comparison_id>.json     # 配对资格、状态、null或真实指标
  program_ir/<run_id>/<ir_id>.json      # B3/S系列产物；当前不生成
  reports/                             # 离线验证、只读审计、汇总
  docs/                                # 三阶段审查、运行指南、实现证据与目录树
```

`standards`不复制进`runs`，生成器只接收对应variant文本；`executions/workspace`只允许task prompt/input、已冻结技能和工具。判题器由控制进程读取隐藏标准，模型不能读取。**文件隔离不是操作系统沙箱**：本版不提供任意代码/通用Agent的安全执行环境；未来executor必须采用allowlist工具或受控容器/账户，并核验可访问路径。官方资源可能含对应条件的source excerpt，B0保留；但不得给退化运行混入clean资源。是否“只技能”需如实报告资源内容权限。

## 3 对象字段与生命周期

下表`必`表示必填，`可`表示可选，`条件`给出触发条件。未写可选的字段默认必填。数组可以为空仅在明确允许的位置。所有固定对象冻结后只创建新版本，不编辑原有版本后重算hash。单次结果在结束时封存，追加语义评审或判题使用独立文件。

### 3.1 case

字段：schema_version:str(必)；case_id:str(必)；case_key:str(必)；version:int≥1(必)；title:str(必)；status:draft|frozen(必)；source_id:str、source_version:str、family_id:str、split:development|validation|heldout_test(均必)；usage:development_only|research(必)；source_record:path、source_file:path、source_sha256:hash、contract_file:path、task_files:path[]非空、variant_files:path[]非空(均必)；official:{domain:str,domain_type:str,family_name:str}(必)。

位置cases/<case_key>/case.json，登记时创建，审核来源和测试后冻结。全部是固定标准。ID按source/family/split和所有子实体交叉核验。旧对应case.json；缺source/family/task/variant身份，旧ready改称frozen，不再暗示任务ready。

### 3.2 source

字段：schema_version；case_id；source_id；source_version；family_id；origin:{kind:locally_authored|repository|publication|web|other,uri:str或null,revision:str或null,license:str或null,unknown_reason:str或null}；document_file:path；document_sha256:hash；description:str。uri/revision/license未知必须给unknown_reason，不能编造作者、许可、commit。

位置cases/<key>/source.json，采集材料时创建，变体前冻结。文件哈希是字节身份，不等于上游版本；本地未有git commit时使用文件清单，不捏造commit。当前case001从明确“开发测试样例”的源文档登记locally_authored，外部来源未知。旧代码无对应。

### 3.3 family

字段：schema_version；family_id；name；grouping_basis:str；source_ids:str[]非空；review_status:pending|reviewed；review_note:str。位置catalog/families.json中的对象列表。数据划分前创建、独立审核后冻结。全部固定；name不作ID。source_ids必须恰好覆盖该family注册来源。待审研究family不得用于正式heldout。当前仅case001可保守归为人工订单CSV开发族，不宣称已获得外部泛化家族。旧无对应，禁止自动用family_name构造独立样本。

### 3.4 split

字段：schema_version；split_id；version:int；status:draft|frozen；policy:str；assignments:{case_id,source_id,family_id,split}[]；heldout_locked:bool；formal_ready:bool；reason:str。位置catalog/split.json。按source/family/重复文档连通组划分后创建，任何模型调参前冻结。当前formal_ready=false且heldout_locked=false。同source或family不得跨split，完全相同文档sha跨split也拒绝；语义近重复仍需人工审查，自动哈希不能证明无近重复。

### 3.5 variant

字段：schema_version；variant_id；version:int；case_id；source_id；source_version；family_id；condition:clean|degraded；input_file:path；input_sha256:hash；clean_variant_id:str；clean_sha256:hash；contract_id:str；degradation_file:path或null；status:frozen。clean的clean_variant_id必须等于自身、两个hash相等且degradation_file=null；degraded必须引用同case的clean且hash不同。

位置cases/<key>/variants/*.json。文档内容完成后创建，模型运行前冻结。全部固定；生成repeat_id不再混在variant里。旧degradation配方中混有repeat_id且无variant_id。不得用编辑SKILL.md代替文档变体。

### 3.6 degradation

字段：schema_version；degradation_id；case_id；variant_id；type:str；severity:{value:number≥0,unit:str}；seed:int≥0；generator:{file:path,sha256:hash,version:str}；parameters:object；edits:{start:int≥0,end:int≥start,before:str,after:str}[]非空；recoverability:{status:pending|recoverable|irrecoverable|conflicting,reviewer:str或null,evidence:str,rule_ids:str[]}。

位置cases/<key>/degradation/*.json。构造时创建、语义审核后冻结。编辑坐标统一为clean Unicode codepoint半开区间，按start递增、无重叠，before必须精确匹配；确定性应用edits须重建variant文本。生成器版本/hash与文件核验，不能靠“脚本存在”证明调用过；未来LLM构造另存真实调用证据。主实验运行只接收recoverable并且覆盖全部规则ID的审核记录；pending不等于失败，需审核；不可恢复组另设计契约，当前入口拒绝。

### 3.7 contract

字段：schema_version；contract_id；case_id；version:int；source_id；source_version；source_sha256；rules:{rule_id,source_text}[]非空且唯一；review_status:pending|reviewed；review_note:str。

位置standards/<key>/contract.json。根据原文独立写标准时创建、运行前冻结。每条source_text必须在clean中出现；引用匹配是出处检查，不证明其逻辑完整。全部固定，删除旧verdict/execution，原pending在迁移记录保留。实际语义verdict属于semantic_reviews，不回写contract。

### 3.8 task

字段：schema_version；task_id；case_id；source_id；family_id；split；purpose:development|validation|heldout_test；contract_id；judge_id；prompt:str；inputs:{filename:str:content:str}非空；expected:{outcome:success|error,outputs:{filename:content},error_record:int或null,error_field:str或null}；covered_rule_ids:str[]；coverage_note:str。

位置standards/<key>/tasks/*.json。测试设计时创建、执行前冻结。预期输出是标准，不能当actual。文件名只允许本任务简单文件名，拒绝路径穿越。当前11个fixture全部purpose=development，覆盖映射未知可空但必须说明；不得把已有开发测试改标heldout。fixture兼容副本冻结并核验与task逐项一致，避免两套答案漂移。异常expect=error若实际正确报错且无输出应判通过，不能把预期错误当任务失败。

### 3.9 run

字段：schema_version；run_id；case_id；source_id；source_version；family_id；split；variant_id；method_id；generation_repeat:int≥1；kind:preflight|generation；status；input_sha256；dataset_freeze_sha256；comparison_fingerprint:hash或null；structural_pass:bool或null；semantic_status:pending|not_applicable；execution_status:not_run；failure:{category:infrastructure|generation|evidence|interrupted|unknown|none,stage:str或null,evidence:str[]}；program_ir_status:not_applicable|not_run；started_at_utc:str；finished_at_utc:str或null。

位置runs/<run_id>/run.json，准备执行时创建，结束后与input/config/trace/official一起封存。模型/提示/参数/代码/环境详细版本在config快照和实际trace中，run以hash关联；服务端模型未返回版本时不捏造。旧status.json保留兼容，但run.json为规范索引。`generation_repeat`不是模型seed；preflight不纳入生成比较。

### 3.10 execution

字段：schema_version；execution_id；case_id；source_id；family_id；task_id；contract_id；judge_id；run_id:str或null；mode:generated_skill|reference|no_skill；execution_repeat:int≥1；status:not_run|running|completed|failed|blocked；failure_category:none|infrastructure|generation|execution|unknown；reason:str；executor:{id:str,version:str,model:str或null}；input_before:{filename:hash}；input_after:{filename:hash}；actual_outputs:{filename:content}；error:{record:int或null,field:str或null,message:str}或null；exit_code:int或null；started_at_utc:str；finished_at_utc:str或null；dataset_freeze_sha256:hash；run_checksums_sha256:hash或null；standard_hashes:{path:hash}。

位置executions/<id>/execution.json。收到具体执行请求才创建，未执行记录可创建明确not_run计划，不自动批量填充空结果。generated_skill必须引用同case且非preflight的封存run，reference/no_skill的run_id=null并明确方法。实际发生后才填写actual。完成后封存，判题另存。当前只实现reference离线闭环和future executor状态接口；不模拟模型执行。

### 3.11 judge 与 judgment

judge标准字段：schema_version；judge_id；case_id；version；implementation_file；implementation_sha256；reference_file；reference_sha256；policy:str；limitations:str[]。位置standards/<key>/judge.json，在运行前创建冻结。规则由contract确定，不从待测技能反推。

judgment结果字段：schema_version；judgment_id；execution_id；case_id；task_id；judge_id；status:passed|failed|not_run；passed:bool或null；checks:{name:str,passed:bool,reason:str}[]；reason:str；execution_checksums_sha256:hash；judge_sha256:hash；created_at_utc:str。位置judgments/<id>/judgment.json。实际judge执行后创建并封存。not_run时passed=null且checks为空；passed/failed必须与全部检查结果一致。检查内容包括输出字节、错误位置/字段、无额外输出、输入不变，参考实现与错误变体离线验证。

### 3.12 comparison

字段：schema_version；comparison_id；clean_run_id；degraded_run_id；case_id；source_id；family_id；method_id；generation_repeat；comparable:bool；reasons:str[]；clean_status:object；degraded_status:object；eligible_for_skill_quality_comparison:bool；semantic_score_delta:number或null；task_success_delta:number或null；metrics_status:not_run|computed；metric_reason:str。

位置comparisons/<id>.json，两个封存run已有后创建。核对条件、source版本、clean哈希、方法/配置/代码/环境/固定标准、repeat、baseline绑定、契约fingerprint重算及封存。允许干净或退化生成失败进入配对；preflight未运行不能配对。当前没有真实技能执行时metrics_status=not_run、delta=null。后续聚合必须依据预登记计划并关联execution+judgment；本次不生成bootstrap假结果。

### 3.13 program_ir

字段：schema_version；ir_id；case_id；source_id；variant_id；run_id；ir_version；status:not_run|generated|invalid|validated；goal:str或null；inputs:str[]；preconditions:str[]；steps:{step_id:str,action:str,depends_on:str[],kind:action|for_each}[]；branches:{condition:str,then_step_ids:str[],else_step_ids:str[]}[]；invariants:str[]；outputs:str[]；checks:str[]；unresolved:str[]；provenance_file:path或null；validation_reason:str。

位置program_ir/<run_id>/<ir_id>.json，B3/S0–S3生成或验证时才创建；未实现时在run中记not_run，不制造空IR文件。validated仅表示schema及DAG验证，语义审查独立。steps ID唯一、依赖只能指向更早节点；branch引用必须存在。B0、B1/B2接B0保留官方原生SkillDraft/SkillSpec/SKILL.md，program_ir_status=not_applicable。参考IR只能在隐藏标准中；运行IR不可读取参考IR补齐。

## 4 冻结和运行前验证

1. 对case、source、family、split、variant、degradation、contract、task、judge做必填/类型/枚举验证，不接受意外结果字段。机器schema也导出为JSON Schema，运行时只使用明确支持的schema关键字。
2. 全量注册扫描验证ID唯一、引用存在、同case/source/family/split、规范目录归属、原文hash、contract摘录、fixture一致性、clean/degraded编辑重放及可恢复审核。跨案例引用即便hash一致也拒绝。
3. catalog/freeze.json保存catalog、cases、standards的精确文件清单，包含case元数据和judge/reference代码哈希；不包含runs等结果。验证增删改，冻结命令已有清单时只能核验，不覆盖。任何标准变化需新数据发布版本及新seal。
4. 每个run保存dataset_freeze_sha256与比较契约；它锚定封存版本。纯本地hash不能防止拥有所有文件权限的人同时重写数据和所有锚，此限制如实记录；正式发布需另保留只读/外部登记的seal。
5. 校验失败在模型调用之前返回非零。错误配对也须在调用前拒绝。离线negative tests用临时拷贝制造错误，不写入研究数据。
