
# 多 CSV 订单最新记录合并规范

Source ID：`src-orders-merge-latest-clean-v1`  
Workflow ID：`wf-orders-merge-latest-v1`

## 1. 适用范围

本流程接收任务显式提供的有序 CSV 文件列表和一个输出路径。它合并所有输入记录，并为每个订单保留一个最新版本。金额计算、客户汇总、目录扫描和无时区日期推断不属于本流程。

## 2. 输入与输出契约

- 输入列表不能为空。必须按任务列出的文件顺序处理，不得改用目录枚举或文件名字典序。
- 每个输入文件为 UTF-8 CSV，带表头且恰有 `order_id,updated_at,payload` 三列。
- `order_id` 是非空、大小写敏感的字符串。必须保留前导零，不得转换为数值或自动修剪字符。
- `payload` 是不透明字符串。CSV 中的逗号、引号和合法换行按 CSV 规则解析；获胜记录的原字段值必须保留。
- `updated_at` 只接受秒级 ISO 时间：`YYYY-MM-DDTHH:MM:SSZ` 或 `YYYY-MM-DDTHH:MM:SS±HH:MM`。日期、时间和数值偏移必须有效；无时区、不可解析、非法日期和不符合该语法的值均非法。
- 输出路径由任务指定，必须是尚不存在的新文件，不能等于任何输入路径。
- 成功输出使用相同三列。每个订单一行，时间转为等价 UTC 表示；输出行顺序不作要求。

## 3. 处理规则

### SRC-R01：读取全部输入

读取任务列表中的每一个 CSV，不能只处理第一个文件，也不能遗漏空数据文件之后的文件。

### SRC-R02：建立唯一输入顺序

全局输入顺序先按任务文件列表顺序，再按每个文件中的数据记录顺序排列。表头不计入数据记录序号。

### SRC-R03：先校验全部记录

在选择获胜记录或创建输出前，校验所有文件和所有记录。即使一条重复记录最终会被淘汰，它的时间和字段仍必须合法。

### SRC-R04：统一到 UTC 后比较

将每个合法时间解析为带时区的时刻并转换到 UTC 后比较。不得直接比较原始字符串，也不得忽略偏移或使用机器本地时区。

### SRC-R05：只按订单 ID 分组

只使用完整 `order_id` 字符串分组，不得按 payload、时间或数值化后的订单号去重。

### SRC-R06：保留最新整条记录

每组选择 UTC 时刻最新的输入记录。`order_id`、`updated_at` 和 `payload` 必须来自同一条获胜记录，不能拼接不同记录的字段。

### SRC-R07：并列时取输入顺序靠后者

若同一订单的两个记录代表同一 UTC 时刻，保留全局输入顺序更靠后的记录。该规则同时适用于同文件和跨文件并列。

### SRC-R08：非法时间使整批失败

任意记录的 `updated_at` 非法时，停止整个批次并报告错误。报告应定位输入文件、该文件中的数据记录序号和字段名。不得跳过坏行后继续成功。

### SRC-R09：输入保持不变

运行前后所有输入文件的内容、路径和存在状态必须不变。

### SRC-R10：只创建新的指定输出

成功时只在任务指定的新路径创建结果。输出路径等于输入或已经存在时必须报错，不能覆盖。

### SRC-R11：失败不留下结果文件

任何校验、读取、解析或写入前置检查失败时，不得留下指定结果文件或部分结果。不得用空结果伪装成功。

### SRC-R12：输出满足完整契约

输出必须可作为 UTF-8 CSV 解析，包含正确表头、唯一订单键、正确获胜整行和 UTC 时间。若全部输入只有合法表头，成功结果为只有表头的新文件。

## 4. 接口错误

空文件列表、文件不可读、空文件、缺列、多列或少列、空 `order_id`、无效 CSV 和非法输出路径均属于输入或接口错误，必须停止且不生成结果文件。错误报告应定位可定位的文件、记录和字段。

## 5. 示例的地位

例如，`2026-01-01T09:00:00+08:00` 等于 `2026-01-01T01:00:00Z`。示例只帮助理解 UTC 转换，不取代以上规则，也不包含任何评测任务答案。

## 6. 完成条件

只有在全部输入已读取并通过校验、每个订单的获胜整行已按上述规则确定、指定新文件成功写出且输入未改变时，任务才算成功。任何失败均需报告且不得留下结果文件。
